# TVCheck / lgtv — технический паспорт проекта

> Назначение файла: единая точка входа для будущих правок алгоритма, интерфейса, skins, упаковки и документации.
> Источник истины по поведению — исходники проекта. `dist/` — собранный артефакт, а не место для ручной разработки.

## 1. Назначение программы

TVCheck проверяет, насколько видеофайл или папка с видео соответствует ограничениям выбранного телевизора. Программа:

- читает контейнер и метаданные через MediaInfo CLI;
- проверяет видео-, аудио- и субтитровые дорожки по JSON-профилю телевизора;
- при полном анализе читает пакеты через FFprobe и измеряет средний поток и пиковый поток;
- отдельно оценивает режимы USB и DLNA/сети;
- показывает результат в GUI и CLI;
- сохраняет JSON/TXT-отчёты;
- умеет добавлять пункт Windows-контекстного меню;
- не декодирует фильм полностью, не конвертирует и не изменяет исходные файлы.

Текущая модель телевизора в комплекте — `LG UK6300PLB`, профиль ПО `05.50.70`. Профиль не является эмуляцией телевизора и не может гарантировать воспроизведение: он формализует проверяемые ограничения из документации.

## 3. Архитектура и поток данных

```text
Windows / пользователь
        |
        +-- TVCheck.exe без --cli
        |       |
        |       +-- gui.Application
        |               |
        |               +-- очередь событий Queue
        |               +-- поток проверки зависимостей
        |               +-- поток сканирования
        |               +-- backend.iter_reports
        |
        +-- TVCheck.exe --cli
                |
                +-- main.main
                        +-- backend.iter_reports

backend.iter_reports
        |
        +-- tv_profiles.get_profile
        +-- find_mediainfo / read_metadata -> MediaInfo JSON
        +-- bitrate.measure -> FFprobe packet stream
        +-- engine.assess(..., mode='usb')
        +-- bitrate.apply(..., mode='usb')
        +-- engine.assess(..., mode='network')
        +-- bitrate.apply(..., mode='network')
        +-- итоговый report с playback.usb / playback.network
```

Инвариант: движок совместимости и измеритель битрейта не должны зависеть от виджетов Tk/Qt. Новый интерфейс обязан использовать их как сервисы и не переписывать правила анализа.

## 4. Алгоритм проверки

### 4.1. Выбор источников

`backend.iter_reports()` принимает:

```python
iter_reports(
    path,
    recursive=True,
    mode='usb',
    mediainfo='',
    stop_event=None,
    profile_id='lg-uk6300',
    full=False,
    link_mbps=None,
    progress=None,
)
```

1. Путь очищается от внешних кавычек, переменных окружения и `~`.
2. Если путь — обычный файл, он проверяется независимо от расширения.
3. Если путь — папка, `os.scandir()` обходит её в стабильном порядке.
4. Для папки выбираются расширения из `backend.EXTENSIONS`.
5. Символические ссылки и junctions не обходятся, чтобы не получить циклы или выход из выбранной папки.
6. Временная ошибка Windows `[WinError 50]` при поиске анализатора, `stat`, MediaInfo или FFprobe повторяется до четырёх раз с паузами; после исчерпания попыток отдельный файл получает финальный `error_report`, а список продолжает обработку.
7. Ошибка доступа к отдельному файлу/папке превращается в отдельный `error_report`, а не останавливает весь список.
8. Вложенные папки обрабатываются только при `recursive=True`.

### 4.2. Получение метаданных

Для встроенного CLI запускается примерно такая команда:

```text
MediaInfo.exe --Output=JSON --Language=raw --Full <file>
```

Обрабатываются ошибки запуска, timeout 45 секунд, ненулевой код выхода, невалидный JSON и отсутствие видео/аудио-дорожек. Необязательная MediaInfo DLL запускается в изолированном дочернем процессе через `main.py --probe-json`, чтобы нативная библиотека не могла заморозить GUI.

### 4.3. Проверка метаданных в `engine.assess`

`engine.assess(path, metadata, mode, profile)` — независимая JSON-сериализуемая функция. Она:

1. Находит `General`, `Video`, `Audio`, `Text`/`Subtitle` дорожки.
2. Нормализует контейнер по формату и расширению.
3. Проверяет контейнер против `profile['containers']`.
4. Проверяет кодек видео, профиль, level, разрешение, FPS, bit depth, chroma и лимиты.
5. Проверяет кодек аудио, профиль, контейнерную связку, UHD-условия и режим USB/network.
6. Учитывает альтернативные дорожки: несовместимая дорожка не делает весь файл красным, если остаётся совместимая или требующая проверки дорожка.
7. Выносит субтитры в информационную область: субтитры не переводят совместимый фильм в жёлтый статус.
8. Добавляет предупреждение при непроверенном пользовательском профиле.
9. Формирует `summary`, `issues` и отдельные результаты для каждой дорожки.

Основные статусы движка:

```text
ok     — ограничений по проверенным данным не найдено
warn   — есть риск, неизвестный параметр или ограничение доставки
fail   — найдено несовпадение с профилем
error  — файл или источник не удалось прочитать
info   — информационная запись, применяется прежде всего к субтитрам
```

В GUI эти статусы отображаются через `gui.STATUS`:

```python
{
    'ok': 'ОК',
    'warn': 'Проверить',
    'fail': 'Не подходит',
    'error': 'Ошибка',
    'info': 'Справка',
}
```

В CLI используются более явные русские слова: `ОК`, `ВНИМАНИЕ`, `НЕСОВМЕСТИМО`, `ОШИБКА`, `СПРАВКА`.

### 4.4. Измерение битрейта

Проверка MediaInfo выполняется быстро и является основным режимом. При `full=True` `bitrate.measure()` дополнительно запускает FFprobe два раза и читает весь файл для измерения среднего и пикового битрейта.

Сначала читаются заголовки:

```text
-v error -show_entries stream=index,codec_type:stream_disposition=attached_pic:format=duration,start_time -of json
```

Затем читаются пакеты:

```text
-v warning -show_packets -show_entries packet=stream_index,dts_time,pts_time,duration_time,size -of compact=p=0:nk=0
```

Алгоритм:

1. Берутся только реальные видео- и аудиопотоки; обложки `attached_pic` исключаются.
2. Для каждого пакета выбирается `dts_time`, при отсутствии — `pts_time`.
3. Отрицательные/аномальные временные значения и пакеты без корректного размера пропускаются с диагностикой.
4. Временная шкала нормализуется относительно `start_time`.
5. Пакет попадает в фиксированное окно `floor(relative_time)` длиной 1 секунду.
6. Суммируются размеры по каждому потоку и общая сумма видео + всех аудиодорожек.
7. Средний поток рассчитывается по суммарным байтам и фактическому span.
8. Пик — максимальная сумма байтов одного фиксированного секундного окна.
9. Возвращается `peak_second`, чтобы показать время риска.
10. Если интервалы неполные, временные метки рвутся или не покрывается заявленная длительность, измерение помечается как неполное. Известные служебные сообщения FFprobe, например `Increasing reorder buffer to N`, сохраняются как техническая диагностика и сами по себе не меняют полноту или статус.

Это не мгновенный и не скользящий максимум. Накладные расходы контейнера и сети в сумму не входят. Анализ не декодирует все кадры и не доказывает отсутствие повреждений или прошивочных проблем.

### 4.5. Применение измерения и USB/network

`bitrate.apply(report, measurement, mode, link_mbps, error)` добавляет измеренные данные к report.

- Если пик видео выше `limit_mbps`, дорожка получает `fail`.
- Если пик ближе чем на 15% к лимиту, добавляется предупреждение.
- Если указан `link_mbps`, пик выше скорости даёт риск доставки, а запас менее 20% — эвристическое предупреждение.
- Сетевой режим всегда осторожнее USB: учитываются DLNA/сервер, MIME, direct play, транскодирование и выбор дорожки.
- Полный и корректный USB-анализ без реального риска может вернуть общий `ok`, а несущественные пробелы MediaInfo остаются в `technical_notes`/`technical_track_notes`.
- При неполном анализе полный зелёный результат не выдаётся.

В каждом отчёте сохраняются альтернативные оценки:

```python
report['playback'] = {
    'usb': {'status': ..., 'summary': ..., 'issues': [...]},
    'network': {'status': ..., 'summary': ..., 'issues': [...]},
}
```

Это позволяет показывать пользователю, что совместимость по USB не доказывает работу DLNA.

## 5. Контракты данных

### 5.1. Snapshot GUI

Перед запуском создаётся snapshot примерно такого состава:

```python
{
    'path': 'абсолютный путь',
    'mode': 'usb' или 'network',
    'recursive': True/False,
    'full': True/False,
    'profile_id': 'lg-uk6300',
    'profile': {...},
    'link_mbps': число или None,
    'mediainfo': строка или '',
    'started_at': ISO datetime,
    'partial': False,
}
```

После завершения добавляются `finished_at`, `cancelled`/`partial` из события `done`.

### 5.2. Report

Стабильные поля, которые должен уметь отображать любой новый UI:

```python
{
    'path': str,
    'status': 'ok'|'warn'|'fail'|'error',
    'summary': str,
    'container': str,
    'video': [track_report],
    'audio': [track_report],
    'subtitles': [track_report],
    'issues': [str],
    'bitrate': {...},
    'playback': {'usb': {...}, 'network': {...}},
    'mode': str,
    'profile_id': str,
    'full_scan': bool,
}
```

Дополнительные поля, которые нельзя терять при смене UI:

- `technical_notes` — нефатальные технические замечания;
- `technical_track_notes` — замечания по конкретным дорожкам;
- `link_mbps` — введённая скорость доставки;
- `model`, `firmware`, `sources` — контекст профиля;
- `bitrate.complete`, `average_mbps`, `peak_mbps`, `peak_second`, `streams`, `issues`, `note`.

### 5.3. События GUI

Фоновые потоки никогда не изменяют Tk-виджеты напрямую. Они кладут в `self.events` события:

```text
('deps', dependencies)
('progress', (filename, stage, percent))
('report', report)
('done', {'partial': bool, 'cancelled': bool})
```

`Application._poll()` вызывается через `root.after(60, ...)` и только в главном Tk-потоке обновляет виджеты. Это обязательный инвариант для будущего UI-слоя.

## 6. Текущая структура интерфейса

Текущий GUI находится в `gui.py`, класс `Application`. Он остаётся на `tkinter`/`ttk`, но компоновка заменена на UI-kit shell из шести вариантов. Backend, report contract и фоновые потоки сохранены.

### 6.1. Окно и меню

- Заголовок: `TVCheck — проверка совместимости видео`.
- Базовый размер: `1180x760`.
- Минимальный размер: `960x680`, по `TVCheck_UIKit_6_Skins/shared/docs/layout_spec.json`.
- Tk-тема: `clam`.
- Иконка: `assets/tvcheck.ico`.
- Главное меню:
  - `Файл → Выбрать файл…`
  - `Файл → Выбрать папку…`
  - `Файл → Сохранить отчёт…`
  - `Файл → Выход`
  - `Настройки → Оформление → Blue Day / Crimson Night / Green Cozy / Violet Neon / Sakura Red / Slate Blue`
  - `Настройки → Профили телевизоров…`
  - `Настройки → Скорость носителя / сети…`
  - `Настройки → Проверить зависимости…`
  - `Настройки → Добавить в ПКМ`
  - `Настройки → Убрать из ПКМ`
  - `Справка → Что означает ОК?`

### 6.2. Навигация и выбор оформления

Боковой панели нет. Действия доступны через верхнее Windows-меню `Файл / Настройки / Справка`.
В `Настройки → Оформление` находятся шесть radio-пунктов нового набора.
ID сохраняется в `%LOCALAPPDATA%\\TVCheck\\settings.json`, например `01_blue_day`.
Неизвестный или старый ID сбрасывается на Blue Day; старые runtime-скины удалены.

### 6.3. Header

Слева — TV-иконка, `TVCheck` и подпись «Проверка совместимости видео с телевизором».
Справа — крупный баннер выбранного скина с персонажем и окружением из предоставленного набора.
Баннер декоративный, не содержит интерактивных контролов и не перекрывает форму.
При ширине меньше 1050 px арт скрывается, а высота шапки уменьшается с 300 до 286 px.
По умолчанию DLNA/сеть отключён: на главном экране остаётся USB без лишнего предупреждения.
Команда `Настройки → Проверка совместимости по DLNA/сети` сохраняется в настройках пользователя.
После включения первым в строке параметров появляется выбор `USB / DLNA / сеть`, затем флаги анализа.

### 6.4. Форма проверки

Под логотипом находятся:

- выпадающий список ТВ, firmware и статус подтверждения профиля;
- кнопка `Профиль`;
- поле пути и кнопки `Файл…` / `Папка…`;
- режим `USB` / `DLNA / сеть`;
- `Вложенные папки`;
- опция `Битрейт · читать весь файл`, выключенная по умолчанию;
- градиентная кнопка `Проверить` и кнопка `Стоп`.

По умолчанию проверяются только характеристики MediaInfo. Дополнительная опция меняет надпись на
`Проверить + битрейт` и включает чтение всего файла для среднего/пикового потока.
Поля блокируются на время сканирования; меню оформления продолжает работать.
Ошибка проверки зависимостей выводится как результат ошибки, а не бездействующая кнопка.

### 6.5. Activity и progress

Под setup card находится отдельный status-area:

- строка `activity` — текущая стадия (`MediaInfo`, чтение файла, измерение битрейта, готово, ошибка);
- тонкий progressbar 0–100;
- footer со счётчиками файлов и состоянием встроенных анализаторов.

При запуске worker-задачи контролы блокируются, `Стоп` активируется. Отмена устанавливает `threading.Event`; FFprobe может завершаться до 45 секунд из-за ожидания внешнего процесса.

### 6.6. Result banner

В result-area первым расположен result banner:

- иконка состояния `✓`, `!` или `×`;
- иконка и текст не зависят только от цвета текущего скина;
- крупный текст `ОК`, `Проверить`, `Не подходит` или `Ошибка`;
- краткое объяснение;
- отдельные строки `USB: ...` и `DLNA: ...`;
- кнопка `Подробнее →`, открывающая отдельное окно деталей выбранной строки.

Состояние читается текстом и иконкой, а не только цветом.

### 6.7. Пять metric cards

Под result banner выводятся пять карточек UI-kit:

1. `Видео` — нормализованные видеокодеки;
2. `Звук` — нормализованные аудиокодеки;
3. `Средний Σ` — средний суммарный поток;
4. `Пик Σ / 1 с` — максимум фиксированного секундного окна;
5. `Время пика` — положение максимума.

`Σ` означает видео плюс все аудиодорожки. Для нескольких файлов метрики относятся к выбранной строке таблицы.

| `Звук` | Список аудиокодеков |
| `Средний Σ` | Средний суммарный поток |
| `Пик Σ/1с` | Максимальный поток в фиксированном секундном окне |
| `Время пика` | Положение максимума, либо `—` без полного измерения |

Выбор строки обновляет метрики и содержимое трёх вкладок в отдельном окне. Оно открывается кнопкой `Подробнее →`, двойным щелчком или Enter:

1. `Видео и звук` — дорожки, статусы, детали, проблемы и технические заметки;
2. `Битрейт / доставка` — полнота измерения, пики, лимиты, USB/DLNA;
3. `Субтитры · справка` — субтитры без влияния на общий вердикт.

### 6.9. Техническая реализация skins

Источник тем — предоставленный каталог `TVCheck_UIKit_6_Skins`. Runtime-ресурсы:

```text
assets/skins/skin_manifest.json
assets/skins/layout_spec.json
assets/skins/<skin_id>/theme.json
assets/skins/<skin_id>/hero.png
assets/skins/<skin_id>/hero_master.png
assets/skins/<skin_id>/logo.png
assets/skins/<skin_id>/primary_{normal,hover,disabled}.png
```

`gui._load_skins()` читает исходные theme tokens и общую спецификацию размеров.
`Application._theme()` применяет палитру, высоту строк, artwork и состояния кнопки к Tk/ttk.
Цвета, названия и ID взяты из нового набора; старых aliases и layout-файлов на скин больше нет.
`hero_master.png` — широкий кадр исходной сцены после удаления нарисованных кнопок и рамки
методом inpainting и нейросетевого восстановления Real-ESRGAN `realesrgan-x4plus-anime` (4×).
Это реконструкция low-resolution референса, а не новый оригинал HD. Мастера имеют ширину 1584 px.
`hero.png` — пропорциональная версия 640×300 с переходом в фон темы слева и снизу.
Форма сужается при ширине 1050–1180 px, чтобы не перекрывать персонажа и не обрывать градиент.
Градиентные кнопки и TV-логотип подготовлены как PNG; Pillow для запуска приложения не требуется.
Скруглённая общая карточка рисуется Canvas, а таблица, ввод и меню остаются настоящими виджетами.
Прокрутка остаётся native ttk: `_AutoScrollbar` скрывает grid-трек, когда содержимое помещается.
Пользовательские image elements рисуют скруглённый ползунок толщиной 6 px внутри зоны захвата 14 px.
Стрелок, ребристой ручки и системной серой рамки нет; цвета normal/hover/pressed меняются вместе с темой.
Перетаскивание и нажатие на трек используют штатные ttk bindings; Shift+колесо прокручивает таблицу по горизонтали.
Tk сохранён: проблема качества была в тесном увеличенном crop, а не в выводе PNG.
Нейросетевая обработка выполняется только при подготовке ассетов, не при запуске и не при смене темы.

### 6.10. Состояния окна

```text
Создание окна
  -> загрузка профилей и шести skins
  -> проверка MediaInfo/FFprobe в фоне
  -> готово к запуску
  -> сканирование
      -> progress/report
      -> готово и выбран результат
```

Фоновые потоки не изменяют виджеты напрямую. `Application._poll()` остаётся единственным местом применения событий к Tk-представлению.

## 8. CLI, отчёты и интеграция Windows

### CLI

```text
TVCheck.exe --cli "D:\\Movies" --json "D:\\report.json"
TVCheck.exe --cli "D:\\Movies\\film.mkv" --mode network --link-mbps 70
TVCheck.exe --cli "D:\\Movies" --quick --no-recursive
TVCheck.exe --cli "D:\\Movies" --profile my-tv
TVCheck.exe --check-deps
```

Коды выхода:

```text
0   всё ОК
1   предупреждение
2   несовместимость
3   ошибка или пустой список
130 отмена
```

GUI и CLI должны использовать один `backend.iter_reports()` и один `engine.assess()`. Допустимо разное представление, но недопустимы разные правила совместимости.

### Отчёты

- JSON содержит snapshot, профиль, источники, disclaimer и `results`.
- TXT строится функцией `gui.text_report()` и содержит дорожки, bitrate, playback и технические замечания.
- Отчёт должен сохранять неполный статус и диагностические сообщения, а не заменять их общим «неизвестно».

### Контекстное меню

`context_menu.py` регистрирует команды для текущего пользователя через `winreg`. Поддерживаются файл, папка и пункт Windows 11 `Показать дополнительные параметры`. Команда зависит от режима запуска: frozen EXE или `pythonw.exe` из исходников.

### Установка

`packaging/Install.cmd` вызывает PowerShell-установщик, который устанавливает программу в `%LOCALAPPDATA%\\Programs\\TVCheck`, создаёт ярлык и пункт контекстного меню. Права администратора не требуются. Настройки и профили остаются в `%LOCALAPPDATA%\\TVCheck`.

## 12. План переделки skins и интерфейса

### Цель и фактический результат

Цель достигнута в текущем Tkinter-runtime: UI визуально переведён на общий shell из UI-вариантов, а backend, engine, bitrate и report contracts не менялись из-за дизайна. Декоративные изображения не определяют состояние приложения и не перекрывают интерактивные поля.

### Слой 1: сохранённая модель состояния

Существующее состояние `Application` сохранено:

```text
profile
path
mode
recursive
full_scan
link_mbps
dependencies
running
progress
reports
selected_report
activity
error
selected_skin
```

Worker-события `deps/progress/report/done` по-прежнему проходят через `Application._poll()`. Worker-потоки не меняют Tk-виджеты напрямую.

### Слой 2: реализованный skin contract

Каждый skin загружает:

```text
colors.accent / accent2 / bg / surface / text / muted / good / warn / bad
radius.sm / md / lg / xl
spacing.xs / sm / md / lg / xl / xxl
typography.title / section / body / metric
layout.window / topControls / primaryButton / resultCard / metricCards / breakpoints
character.png
```

Один skin содержит только внешний вид, размеры и assets. Правила совместимости, запуск анализаторов и профиль ТВ находятся вне skin.

### Слой 3: реализованный shell/layout

```text
┌ Sidebar ─────┬──────────────────────────────────────────────┐
│ Проверка     │ TVCheck / slogan / skin selector             │
│ Устройства   ├─────────────────────────────────────────────┤
│ Настройки    │ TV + file setup card + character + CTA      │
│ О программе  ├─────────────────────────────────────────────┤
│ dependency   │ activity + progress                         │
│ status       ├─────────────────────────────────────────────┤
│              │ result banner + USB/DLNA                    │
│              │ 5 metric cards                               │
│              │ result table + detail tabs                  │
└──────────────┴──────────────────────────────────────────────┘
```

Sidebar, setup card, result banner, пять metrics и detail tabs реализованы в `gui.py`. На компактной ширине сначала скрывается character-area; основная форма и результат остаются.

### Слой 4: что осталось для будущего Qt-перехода

Текущая реализация намеренно оставлена на Tkinter, чтобы не добавлять новую runtime-зависимость в portable EXE. Если потребуется пиксельное соответствие SVG/QSS-концептам, следующий отдельный этап — вынести controller/view-model и заменить только presentation layer на PySide6/Qt. Backend и report contract мигрировать не должны.

Оставшиеся задачи не являются частью текущей замены skins:

- native SVG-рендеринг вместо подготовленных PNG-crops;
- отдельные полноценные страницы sidebar вместо текущих dialogs;
- автоматические visual regression snapshots для всех шести тем.

### Выбор UI-технологии

Есть два допустимых пути:

#### Минимальный риск: оставить Tkinter

Плюсы:

- не меняется runtime;
- меньше размер и риск упаковки;
- можно сохранить текущую рабочую логику `Application`.

Минусы:

- сложнее повторить скруглённые карточки, SVG, градиенты и точную адаптивность;
- потребуется `Canvas`/растеризация части assets;
- theme tokens придётся вручную маппировать на ttk.

#### Максимальное соответствие UI-kit: PySide6/Qt

Плюсы:

- нормальные layout-ы, `QStackedWidget`, sidebar, SVG через `QSvgRenderer`, QSS и native dialogs;
- проще реализовать карточки, состояния, масштабирование и адаптивность;
- UI-kit README прямо предусматривает Qt/PySide/PyQt-интеграцию.

Минусы:

- новая runtime-зависимость;
- отдельная работа с PyInstaller и Qt plugins;
- потребуется аккуратная миграция, чтобы не продублировать engine/backend.

Рекомендация для точного соответствия показанному концепту: использовать Qt/PySide6 как отдельный presentation layer, но мигрировать только после выделения controller/view-model. Если приоритет — минимальный размер portable EXE и короткая миграция, сначала реализовать skin на Tkinter и Canvas, понимая ограничения SVG.

## 13. Правила, которые нельзя нарушать при UI-рефакторинге

1. Не переносить проверку совместимости в widgets.
2. Не вызывать MediaInfo/FFprobe из главного UI-потока.
3. Не обновлять Tk/Qt widgets из worker thread.
4. Не удалять `playback.usb` и `playback.network`, даже если показывается только выбранный режим.
5. Не терять `technical_notes` и `technical_track_notes`.
6. Не делать цвет единственным носителем статуса.
7. Не использовать full mockup PNG как интерактивный экран.
8. Не считать отсутствие пиковой диагностики зелёным полным результатом.
9. Не превращать предупреждение DLNA в жёсткий запрет USB.
10. Не изменять исходные файлы пользователя.
11. Не подменять заводской профиль только изменением имени модели.
12. Не добавлять новый asset без копирования его в Build.ps1/дистрибутив.
13. Не обещать гарантированное воспроизведение: программа анализирует ограничения, а не телевизор.
